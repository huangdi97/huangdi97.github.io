## 概览

Morn 是一个工作与组织控制平面：一个面向受治理的工作、actor、产物、结果、演进与分布式持久化执行的领域无关内核。

仓库 README 将当前状态描述为 **v1.0.0-rc.1，本地 GA 完成**。Workbench、Studio、Console、Hub 四个产品界面共用一套 axum 后端与一套 React / Vite 前端，另有 Tauri v2 桌面外壳与开发者命令行工具。

本页的阅读方式：行为层面的主张来自公开仓库，所有数字均引用 README，而非本站亲自运行所得。本站不宣称任何通过率。

## 问题

多数工作流与项目管理工具把同一件事存了两份：决定要做什么的记录，与实际发生了什么的记录。两者会漂移，而系统本身毫不知情。

「持久化智能体执行」会让这件事更糟而不是更好。一旦软件能够自行采取行动，真正有意思的问题就不再是它能做什么，而是哪些效应可逆、谁批准了它，以及某个节点中途挂掉之后什么仍然成立。

由此得到三条不可拆分的要求：

- **权威状态变更**必须能与派生视图区分开。一个可以直接写入权威状态的运行时，也能悄无声息地毁掉它。
- **不可逆效应**必须与可逆效应走不同的闸门。一刀切的权限模型要么什么都拦住，要么放行太多。
- **检查点**必须扛得住节点故障，否则工作会从一个不清晰的位置重启，并产生重复效应。

## 为什么重要

智能体与自动化产品通常用事后补上的日志查看器来解决这个问题。那记录了发生了什么，却没有约束什么被允许发生。

如果约束被放进写入路径本身，三个属性就从愿景变成结构性的：行动可审计，因为动作统一经过一个网关；中断可恢复，因为租约与检查点是运行时的一部分；变更可逆，因为晋升生成的是新版本加回滚点，而不是原地修改生产环境。

## 产品 / 研究主张

1. **语义必须不可被重定义。** 内核原语是固定的；插件扩展的是表面，绝不是含义。
2. **约束写入的是效应类别，而不是角色。** 一个效应有多难撤销，比请求者的身份更适合作为授权边界。
3. **持久化既是存储问题，也是协调问题。** 只有检查点而没有租约，只消除了两种故障模式中的一种。
4. **领域中立性是一次检验。** 零领域包也能启动运行，证明内核没有夹带任何领域假设。

## 系统设计

权威状态变更只走一条路径：

```text
提案 → Schema → 领域 → 策略 → 审批 / 仿真
     → 动作网关 → 提交 → 校验 → 账本 / 结果
```

运行时与 provider 位于稳定契约之后，不能直接提交权威世界状态。效应分级为 E0 只读到 E3 不可逆：E3 需要审批，E2 需要补偿方案。

## 架构

**语义内核**（`morn-kernel`）— 身份、工作空间、策略、审批、只追加账本与版本化契约。

**运行世界层**（`morn-world`）— 对象、关系、事件、状态快照、状态差异与结果，统一由受治理的网关收口。

**工作与组织**（`morn-work`、`morn-organization`、`morn-actor`）— 工作包、验收规格、持久化运行时、角色槽位、成员与 actor，其间关系以契约数据保存。

**演进**（`morn-evolution`、`morn-foundry`、`morn-assurance`）— 候选 / 分支 / 评估 / 晋升与生产环境隔离，配套方案编译器、认证与回滚点。

**能力织物层**（`morn-capability`、`morn-harness`、`morn-runtime`、`morn-integration`）— 可替换的 provider、运行时与连接器；连接器只能通过受治理的 token 写入。

**节点与进程**（`morn-node`、`morn-process`）— 跨双节点的领取、检查点、租约、故障转移与去重。

**领域 SDK**（`morn-domain-sdk`、`morn-package`）— 领域包的安装、启用、停用、升级、卸载，并保留历史。

## 核心能力

**受治理的动作网关。** 四类效应配四道不同的闸门，行动的代价决定采取它所需的摩擦力。

**不可变产物。** 修改会生成带血缘的新版本；旧版本始终可读。

**非侵入式晋升。** 用新版本与回滚点替换旧版本——生产环境永不被原地编辑。

**双节点持久化执行。** 跨两个节点实现领取、检查点、租约、故障转移与去重。

**零领域启动。** 内核在未安装任何领域包时即可启动运行；参考领域包 `biolab-reference` 独立存放并以 feature 开关隔离。

## 技术决策

**22 个 crate，按依赖顺序排列。** kernel → world / work → capability → app。这个排序本身就是一条编译期声明：谁可以依赖谁。

**领域包是被安装的，不是被 import 的。** 领域知识只能通过公开 SDK 进入，内核不可能意外吸收领域假设。

**一个验收脚本。** `scripts/run_all.ps1` 覆盖 fmt、clippy、Rust 测试、前端检查、桌面端构建与 UI / E2E 冒烟——验收是被脚本化的，而不是被描述的。

**阻塞项被记录而不是隐藏。** README 中写明两个外部阻塞项：真实的 DeepSeek Harness 冒烟需要真实凭据，真实的 BioLab 数据试点需要合法数据集。两者都被标注为阻塞，而不是通过。
