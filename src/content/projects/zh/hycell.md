## 概览

HyCell 是一个 AI 虚拟细胞基础设施项目。当前的产物 HyCell-JEPA 是 v0.1 工程 MVP：面向 HDF 衰老、再生与扰动规划的细胞世界模型原型。

项目问的是一个刻意收窄的工程问题——系统能否把细胞状态动力学表示为紧凑、可检查的信念状态上的转移，同时让校验、规划、真实数据接入与文档都诚实到可被评审？在 v0.1 中，答案是一个可在本地运行的原型。

HyCell 不是什么，同样需要说清楚：不是医疗建议，未经湿实验验证，不是完整的虚拟细胞，也不是转录组规模的生成模型。

## 问题

细胞扰动建模存在一个现实张力。

全转录组生成昂贵、吃数据，而且很难在小规模 MVP 内被验证。生物学规划需要可解释的状态转移与明确的边界，而这必须在任何关于干预的结论被提出**之前**就具备。与此同时，公开单细胞矩阵确实适合做工程验证——而它们的元数据缺失，恰恰让夸大结论变得非常容易。

这个领域真正的失败模式不是模型不好，而是把软件冒烟测试当成生物学发现来汇报。

## 为什么重要

AI for Science 系统需要的远不只是一个 checkpoint。它需要数据契约、带来源的标签、明确的边界、可复现的命令，以及阻止把工程管道包装成生物学结论的护栏。

HyCell 就是围绕这种工程纪律构建的。模型被刻意做小；它周围的一切——数据加载器、schema 校验、编码器、转移建模、校验器输出、规划器报告、演示界面、验收脚本、持续更新的文档——才是更大规模虚拟细胞工作真正需要的东西。

## 产品 / 研究主张

1. **紧凑可检查，优于高维且好看。** 评审者应当不需要 GPU 就能审计状态。
2. **干预是转移，不是一次生成。** 建模 `b + a + c + h` → 下一信念状态，并让每一项保持可分离。
3. **校验器属于模型循环的一部分。** 未通过合理性或过度宣称检查的预测，必须以结构化形式说出来。
4. **在被证明之前，真实数据只用于工程验证。** 公开矩阵验证的是管道，它本身不验证生物学。

## 系统设计

转移接口是系统的中心：

```text
b_t + a_t + c_t + h_t  →  b_{t+1}
```

其中 `b` 是生物信念状态，`a` 是干预/动作，`c` 是上下文，`h` 是细胞系统专属的适配器状态。保持它们彼此分离，正是同一个核心能够跨细胞系统复用、而不是被重新训练进数据里的原因。

核心外围的完整流水线：

```text
细胞 → 基因集打分 → 生物状态编码器 ┐
动作编码器 ───────────────────────┤→ JEPA 转移核心
上下文编码器 ─────────────────────┤      ↓
HDF 适配器 h_t ───────────────────┘  预测的紧凑状态
                                          ↓
                              校验器 → 规划器 → 演示/报告
```

## 架构

- **数据层** — 确定性的 toy HDF-like 生成器，加上 GSE130973 Matrix Market 文件的真实数据接入，并对 `.csv`、`.npz` 与可选的 `.h5ad` 做 schema 校验。
- **基因集打分** — 把细胞级数据转换为紧凑、可解释的读数，而非完整转录组。
- **编码器** — 生物状态、动作、上下文与 HDF 适配器编码器，分别接入转移核心。
- **JEPA 转移核心** — 在 toy 紧凑状态上的岭回归转移头。
- **EvidenceGraph** — 把 toy 动作、读数、假设与边界显式链接，让主张与保留意见成为数据而不是散文。
- **生物校验器** — 结构化的 pass / warn / fail 输出。
- **目标状态规划器** — toy 动作序列的 Top-K 搜索，以演示形式呈现。
- **演示** — Streamlit 界面，用于检查 toy 循环与真实数据冒烟状态。
- **验收脚本** — 分目标校验脚本与发布验证脚本。

## 核心能力

**紧凑状态表示。** 基因集打分产出可解释的信念状态特征，而不是高维黑箱。

**转移建模。** 核心从 `b`、`a`、`c`、`h` 预测下一紧凑状态。适配器槽位是接口能够跨细胞系统移植的原因。

**校验。** 每次运行都产出结构化校验输出。在已验收的 toy 流程中，校验器返回的是 warning 而非静默通过——这是预期行为：系统本就应该对自己的 toy 数据保持怀疑。

**规划。** 对 toy 动作序列做 Top-K 搜索并给出距离，同时明确标注输出属于软件演示。

**真实数据冒烟流程。** GSE130973 被接入、校验、摘要与投影——默认上限 5000 细胞 × 2000 基因——作为真实矩阵工程验证。

## 技术决策

**JEPA 式隐空间转移，而非转录组生成。** v0.1 优先保证本地可跑的实验、可检查的读数、校验器与规划器管道，以及在不编造标签或转移关系前提下的真实数据验证。完整生成被推迟到可被验证之时。

**转移接口中的适配器槽位。** `h` 项承载细胞系统专属状态，因此皮肤成纤维细胞适配器与未来的其他细胞系统可以共用同一个转移核心。

**EvidenceGraph 作为一等对象。** 假设与边界是数据，不是会随代码漂移的文档散文。

**诚实标注真实数据。** GSE130973 冒烟数据是未过滤的人类皮肤单细胞数据：`cell_system = skin_single_cell_unfiltered`，仅凭三个 GEO 文件，`state_label` 与 `age_label` 均为 `unknown`。这一点被写进流水线，而不是作为脚注留在文档里。

**把可复现性当作契约。** `pytest`、分目标校验脚本与 `scripts/verify_release.sh` 就是验收标准。

## 工程实现

本地 toy 流程可端到端运行：生成数据、基因集打分、构建 EvidenceGraph、训练编码器、训练转移模型、评估 benchmark、运行规划器。每个阶段都是带配置文件的独立脚本，因此可以单独重跑与检查。

云端流程——RTX 4090 配置、运行脚本与结果打包器——作为可复现脚手架存在，不会静默启动大型任务或下载大型数据集。

## 验证

以下数值来自已验收的 toy 流程，并附有适用范围说明：

- Toy 打分转移数：8（6 条训练，2 条留出评估）。
- 全转移 MSE：0.014585165。
- 校验器状态计数：8 条 warning。

这些数值证明工程管道可以运行。它们不验证生物学，仓库也如此声明。GSE130973 冒烟流程同样只属于真实矩阵工程验证。

没有湿实验验证，没有临床结论，也没有与基础模型的基准对比。这是 v0.1 的性质，不是疏漏。

## 我学到了什么

先写「局限性」这一节，反过来改变了设计。一旦每条主张都必须点明它所依赖的数据，规划器就不再产出建议而是产出演示，校验器也不再是装饰。

适配器槽位是第二个有价值的决定。把细胞系统状态从转移核心中剥离出来，才让一个 toy 实验变成其他工作可以接入的接口。
